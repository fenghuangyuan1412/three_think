# 游戏流程（完整版）

> 本文记录 **three_think 第一版游戏（马尼拉式规则）的完整流程**：一局怎么走、每一步谁决策、
> 与本实现相比原版做了哪些简化。
> 纲领与硬约束见 [`../agent.md`](../agent.md)；每一版做了什么见 [`design-v1.md`](./design-v1.md)。

---

## 1. 一局的完整流程图

```
建局（3–5 人，每人 30 元 / 2 张股份 / 3–4 个小弟）
      │
      ▼
┌─ 每段航程 ────────────────────────────────────────────────┐
│  ① 竞标港务长办事处                                        │
│  ② 港务长买 1 张股份（可选）                                │
│  ③ 港务长从 4 种货里挑 3 种装船                             │
│  ④ 港务长把 3 艘船放进航道 0–5，三船起点之和必须正好 9        │
│  ⑤ 放置小弟 ⇄ 掷骰推船 交替进行（见 §2 步骤表）              │
│       · 第 1、2 轮：有船恰好停第 13 格 → 海盗登船占其甲板     │
│         （多艘候选时由海盗船长挑一艘；海盗不占货仓、不挤人）  │
│       · 第 3 轮：停第 13 格的船直接被海盗劫掠                 │
│  ⑥ 第三次投骰结束 → 谈判阶段（全屏交易界面）                 │
│       · 每人每段航程可向任意玩家转账一次，金额自定            │
│       · 界面右侧回放本轮金额变化与本航程操作，全员确认才放行  │
│  ⑦ 领航员移动（先小后大）——在谈判确认之后、结算之前          │
│  ⑧ 海盗船长决定被劫掠船只的去向（港口 / 修船场）             │
│  ⑨ 利润分配 + 保险理赔                                      │
│       · 每人各自点「我看完了」，全员确认后才继续              │
│  ⑩ 抵达港口的货物涨价 1 档                                  │
└───────────────────────────────────────────────────────────┘
      │
      ▼  任一货物价格达到 30 元？
      否 ──→ 回到 ①（航程序号 +1）
      是 ──→ 游戏结束：现金 + 股份价值 − 每张抵押股份 15 元，最高者胜
```

## 2. 步骤表：放置小弟与掷骰推船如何交替

规则原文：

> 「这个阶段有三个同伙放置回合，每个同伙放置回合后有一个平底船移动回合…
> 在三人游戏中，有四个同伙放置回合与三个平底船移动回合：在第一个同伙放置回合之后，
> 执行第二个同伙放置回合。接着开始第一个平底船移动回合。在此之后，回合的交替顺序
> 与四位元玩家的游戏相同。」

实现（`src/core/voyage.ts` 的 `voyageSchedule`）：

| 人数 | 步骤序列 | 放置回合 | 移动回合 |
| --- | --- | --- | --- |
| 3–5 人（统一） | P M P M P M → **谈判 → pilot** | 3 | 3 |

`P` = 放置小弟、`M` = 掷骰推船。谈判与领航员不在步骤表里：
第三次投骰的「继续」按下后由 `game.ts` 先进入 `negotiation`，全员确认后再轮到
领航员（先小后大），然后才走结算链。

**为什么恰好对齐**：本作每位玩家 3 个小弟、3 个放置回合，每回合放一个正好用完
（官方规则书对 3 人局有"4 小弟 4 放置轮"的变体，本作不采用）。

## 3. 每个阶段：谁决策、决策什么、怎么结算

| 阶段 | 决策者 | 决策内容 | 关键约束 |
| --- | --- | --- | --- |
| 竞标港务长 | 所有玩家轮流 | 出价或过牌 | 起拍 1 元；过牌后本航程不得再进场；出价上限 = 现金 + 未抵押股份 × 12 |
| 买股份 | 港务长 | 买 1 张或跳过 | 价格 = 该货当前黑市价，**最低 5 元**；每航程只能买 1 张 |
| 装货 | 港务长 | 4 种货里挑 3 种，各装一艘船 | 三艘船必须装不同的货 |
| 放船 | 港务长 | 三艘船的起点 | 各自在 0–5，**三者之和必须正好是 9** |
| 放置小弟 | 按港务长起顺时针 | 放 1 个小弟 / 自我克制 | 货仓与海盗船**必须从最低价 / 第一格开始填**；保险处免费且立即 +10 元；过牌后本航程不再放 |
| 掷骰推船 | 自动 | 为 3 种上船的货各掷 1 颗骰子 | **越过**第 13 格才进港；**正好停在**第 13 格会招来海盗；抵达后多余点数忽略 |
| 海盗登船 | 海盗船长（多艘候选时） | 挑一艘停第 13 格的船，全体海盗跳上它的甲板 | 仅第 1、2 轮触发；单艘候选自动登船；海盗不占货仓格、不挤走任何人；第 3 轮起不再登船、直接劫掠 |
| 谈判与转账 | 全员并行（无轮次） | 向任意玩家转账一次（金额自定）/ 确认结束谈判 | 每人每段航程至多主动转出 1 次；正整数、不超现金、不能转给自己；全员确认后才轮到领航员。界面右侧回放本轮金额变化 + 本航程操作 |
| 领航员 | 小领航员 → 大领航员 | 对每艘海上的船各移动一次，或放弃 | 小：每艘 ±1 格；大：每艘 ±2 格；同一艘只能动一次；不能影响已进港 / 进船厂的船 |
| 海盗去向 | 海盗船长 | 每艘被劫掠的船送港口还是修船场 | 送港口则该货物涨价 |
| 利润分配 | 自动 + 全员并行确认 | — | 见 §4；每人各自点「我看完了」，全员确认后才进入涨价 |
| 货物涨价 | 自动 | — | 抵达港口的货物各 +1 档 |

## 4. 利润分配与保险理赔

| 位置 | 拿钱条件 | 金额 |
| --- | --- | --- |
| 货仓（船上） | 该船**抵达港口**且未被劫掠 | 货仓总利润**由格位上的所有小弟均分**（向下取整，余数留在钱箱）；**若甲板上站着登船的海盗，则整船货款归海盗均分，货仓小弟空手而回** |
| 货仓（被劫掠） | 永不 | 普通小弟空手而回；只有**登船的海盗**均分劫掠所得 |
| 货仓（进船厂） | 永不 | 空手而回 |
| 港口 A/B/C | 有船停在该空格 | 该格印的报酬，**由海港钱箱支付** |
| 修船场 A/B/C | 有船停在该空格 | 该格印的赔偿，**由保险仲介者支付**（无人担任则钱箱负担） |
| 保险处 | 放置时 | 立即 +10 元，但之后必须承担全部修船理赔 |
| 海盗船 | 见上 | — |
| 领航员 | 无直接收益 | 只影响船只位置 |

**保险理赔顺序**（规则：「保险仲介者的玩家在付出平底船修理费用之前，首先在航程中得到利润」）：

1. 先结算所有收益（含仲介者自己的）
2. 仲介者按每艘进厂船只的修船场格位金额理赔：格位上有小弟 → 付给该玩家；没有 → 付给钱箱
3. 现金不够 → **自动抵押股份**（每张贷 12 元）
4. 仍然不够 → 付出他能付的全部，**差额由钱箱承担**（无需归还）

## 5. 本实现相对原版规则的处理

### 5.1 原版未定义、由本实现补充

| 情形 | 原版 | 本实现 |
| --- | --- | --- |
| 第一段航程全员过牌 | 未定义（没有在任者可连任） | 起叫者以 **0 元**接任港务长 |
| 只剩一人但该人从未出价 | 未明确 | 不结束竞标，轮到该人，他必须出价或过牌 |
| 玩家现金不足以付最便宜的付费格位 | 「盲目的旅客」可免费放置 | 成为盲目旅客，付出**全部现金**；不能担任保险仲介者 |

### 5.2 简化（与原版不同，已知且有意为之）

| 项 | 本实现 | 原版 |
| --- | --- | --- |
| 起叫者（首段航程） | 固定由**座位第 1 位**起叫 | 「最老的玩家」——数字版无法得知年龄 |
| 海盗登船 | 全体海盗**一起跳上船长挑中的那条船的甲板**（不占货仓格；第 3 轮不登船） | 每位海盗依序决定是否登船、站进货仓空格 |
| 装货到哪条航道 | 由港务长指定（UI 默认按货物顺序） | 港务长自由指定 |
| 得标者 / 仲介者现金不足时的抵押 | **自动**挑选当前单价最低的股份 | 玩家自行选择抵押哪一张 |
| 结算数字 | 货仓利润均分后**向下取整**，余数留在钱箱 | 实物用筹码，不存在小数问题 |
| 被劫掠船只占格 | 在正常进港 / 进厂之后占用剩余空格 | 规则未明确顺序 |
| 行动牌 | **未实现**（原版有 20 张） | 有 |

### 5.3 棋盘印刷数值（**已核实**）

数值已对照 **Zoch Verlag 官方英文规则书**（©2005，内含棋盘实物照与正文例子）核实。
`src/config/board-layout.ts` 的 `PRINTED_VALUES_PROVENANCE` 已置为 `'verified'`。

| 项 | 数值 | 来源 |
| --- | --- | --- |
| 黑市价格轨 | `0, 5, 10, 20, 30`（**5 档**，指示物起始位在 0 下方） | 规则书 Abb. 2b「开局时黑市状态」插图，四列货 × 五行数值 |
| 港口 A / B / C | 费用 `4/3/2`，报酬 `6/8/15` | 规则书 p.4 港口实物照（深圈=报酬、黄圈=费用）；正文 fig.13a「2 punts reached the destination port → ORANGE earns 6, RED earns 8」 |
| 修船场 A / B / C | **与港口完全相同**：`4/3/2` → `6/8/15` | 规则书 p.4 修船场实物照；正文 fig.13b（船厂 A 付 6）、fig.14（付 6 与 8） |
| 货仓 肉豆蔻（棕） | 3 格，费用 `2/3/4`，总利润 **24** | 实物照 + 正文「nutmeg punt of 24 PESOS」 |
| 货仓 丝绸（蓝） | 3 格，费用 `3/4/5`，总利润 **30** | 实物照读数（正文未直接写出） |
| 货仓 人参（米黄） | 3 格，费用 `1/2/3`，总利润 **18** | 实物照读数（正文未直接写出） |
| 货仓 玉（绿） | 4 格，费用 `3/4/5/5`，总利润 **36** | 实物照 + 正文「the 36 PESO profit」 |
| 海盗船 2 格 | 各 **5** 元 | 规则书 p.4 海盗船实物照，两个黄圈都印 5 |
| 骰子颜色 ↔ 货物 | 棕=肉豆蔻、蓝=丝绸、米黄=人参、绿=玉 | 规则书 Abb. 2b 四列颜色 + 正文「the brown „nutmeg die“」 |
| 小 / 大领航员 | `2 / 5` 元 | 规则书 p.4「the space costing 2 PESOS」「the „large pilot“」 |
| 保险处 | 免费放置，立即得 **10** 元 | 规则书 p.4「immediately receives an insurance payment of 10 PESOS」 |

**关键理解修正**：港口 / 修船场的 A / B / C 是**递增的到达门槛**——
A 只要有 ≥1 艘抵达就赔、B 要 ≥2、C 要 ≥3，所以 C 的费用最低（2）而报酬最高（15）。
本实现按「第 N 艘停在空格 N-1」判定，与门槛写法等价。

**仍然不确定的两点**（不影响当前实现）：

1. 蓝 / 米黄 / 绿三颗骰与货物的对应关系，规则书里**没有一句明文**（只有颜色体系推断 + 颜色一一对应）。
2. 港口 / 修船场每格印了几个小弟位：规则书写「there is an accomplice place」（单数），
   但又写「a player can deploy several accomplices on port and shipyard spaces」。
   实物照上每格只见 1 个印刷圆圈，本实现按**每格 1 位**处理。

| 文件 | 覆盖 |

其中「完整一局」用一套简单策略驱动 `applyIntent` 直到 `game-over`，
断言：结束条件是至少一种货价达到 30、胜者是财富最高者、日志覆盖各阶段、同 seed 结果完全一致。

### 浏览器端到端（Playwright，headless Chromium）

从开始界面一路点到游戏结束，实测覆盖全部常规阶段（13 个，含概率出现的「海盗选择登船」）：
竞标 → 买股份 → 装货 → 放船 → 放置小弟 / 掷骰推船交替 →（海盗登船）→ 谈判与转账 → 领航员 →
海盗决定去向 → 利润分配（逐人确认）→ 货物涨价 → 游戏结束。

同时断言：
- 控制台**无报错**、无 `pageerror`
- 棋盘包围盒未被视口截断（`window.__TT__.framing().inside === true`）
- 棋盘上确实挂出了小弟棋子（最多 12 枚 = 3 人 × 4 个）
- 渲染统计：draw call 88–94（预算 150）、三角形约 2.9k（预算 300k）

帧率在软件渲染下为 28–36 fps，**不代表真实 GPU 表现**，标记为**未验证**。
